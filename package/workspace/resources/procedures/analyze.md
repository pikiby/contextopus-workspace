# Analyze actual Contextopus operations

This is the canonical analyze procedure. Obtain this procedure before analysis; call operations through `read` or `write`; prefer `workspace.<operation>`. Fetch needed references with `guide(procedure="reference/<name>")`. The short `w-analyze` skill obtains this procedure when it is not already available for the task. For knowledge quality, consistency or organization, use the audit procedure. Analysis investigates what an agent actually did and what evidence establishes it.

1. **Set the scope before a large analysis.** Resolve the selected context name(s), the user's question, a finite period or an explicit task/cycle/import, plus narrower dates where relevant, and operation filters. Storage is owned by the connected server. If neither dates nor a task/cycle/import are specified, freeze `until` now and use the preceding seven days; state this assumption. Read current INSTRUCTIONS to govern the analysis itself; historical instructions govern judgments of past work, never current authorization. Do not guess an actor or session from a directory or timestamps. Identify the recorded plugin version and contemporaneous instruction/procedure revisions, including changes within the period. Missing identifiers or revisions remain explicit unknowns. Distinguish evaluating work within its own era from comparing eras. Never silently scan years of events.
2. Read [history and analytics](procedure:reference/history-analytics). Start with bounded metadata and measured summaries using `analytics_query` or `analytics_report`. Narrow progressively to candidate operations and exact event IDs. Keep the frozen upper boundary on all queries so analysis calls are excluded. Page only within the agreed scope; report partial coverage and extend the scope explicitly when needed. Independent reads may lack task/cycle IDs and cannot silently be attributed to that agent.
3. Inspect selected `analytics_read(event_id)` records: parameters, results/errors, duration and version references. Replay selected Git-backed source references with `analytics_reference_read`; retained unmatched legacy bodies use `analytics_blob_read`. Use `history_index` and `history_lineage` to locate versions and declared transformations, then `history_read`/`history_diff` for the exact necessary Git content. Use recorded instruction and procedure versions for historical judgments. A procedure fingerprint detects an era change but needs a matching release/source to recover its text; report unavailable historical procedure text. If the rule revision is unknown, do not retrospectively apply today's rule. A derived index or an agent's transformation declaration is not semantic proof. Dirty or unversioned text may prevent exact replay; report that gap.
4. Connect each finding to events and the relevant returned material versions, historical rules and task/answer evidence. Distinguish search excerpts, full bodies, repeated reads, unique records and declared link traversal. Reading does not establish application or actual model use. An unlabelled read does not prove a link was ignored. A `started` event has unknown outcome. File changes or timestamps alone do not establish authorship. Inspect prepared/applied changes and errors as needed for the question.
5. Import host evidence only from the exact user-selected file authorized for analysis/import, using `analytics_import(source_path, adapter, user_request, session_id?)` through execute. Do not discover other sessions automatically. Imported messages and drafts remain separate evidence until independently linked. External reads, required-source refreshes, final answers and skipped Contextopus calls may be unobservable; say "not established" where appropriate. A fresh required-source check now does not establish that an earlier agent performed it.
6. Report in the conversation language: selected contexts/question, frozen dates and filters, era/instruction basis, coverage; findings with exact event IDs, Git revisions and facts distinguished from inferences; measured read/search/link/change/error counts; unknowns and supported corrections. Contextopus duration totals are not total task time. Bytes are not tokens. Token savings, cost, benchmark superiority and causal improvement require host usage and comparable control runs; do not claim them from this journal.

Return the analysis in chat. Only an explicit request to retain an assessment authorizes `analytics_evaluate` through execute: include its scope, contemporaneous instruction basis, criterion, assessment and evidence event IDs. This records an assessment separately from objective events and knowledge. Analysis does not authorize knowledge edits, instruction changes, arbitrary history imports or implementation of proposed fixes.

## Search effectiveness

Use `core.search_events` with the same frozen period and selected context/task/instruction revision, then `core.search_event` for relevant IDs. These records retain algorithm/version, effective parameters and origins, candidate IDs/revisions/distances, selected fragments/materials, boundary and technical truncation. `workspace_event_id`, when present, links the same call to the Workspace journal and its exact historical content references. Query hashes identify exact repeats without storing query text; use authorized host or Workspace evidence for wording and user intent.

Evaluate the whole search episode: necessary questions covered, irrelevant reading, repeated queries, parameter changes, durations and actual host token usage when available. Check quality and compliance separately. Support conclusions of too narrow/broad selection, unsuitable algorithm or unhelpful changes with task evidence and boundary candidates; otherwise report insufficient evidence.

`core.search_replay(event_id, selection)` applies a candidate algorithm to the recorded pool without new embeddings. It reports added/removed materials or distinct fragments. Optional `relevant_keys` supplies explicit material relevance labels for precision/recall comparisons; report who supplied those labels and their scope. These metrics do not independently establish answer correctness or global recall. A truncated pool cannot show omissions beyond it; a broader retrieval against today's corpus is a separate observation, not reconstruction of the historical pool. Current algorithm code/version used for replay is reported separately from the original. Never change project rules automatically from an assessment.
