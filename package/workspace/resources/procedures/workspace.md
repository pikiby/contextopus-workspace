# Work with Contextopus

Obtain and read the applicable procedure before acting. This procedure covers ordinary work and independent retrieval; reuse it between phases. Refresh used procedures after a plugin update. Questions steer unfinished work; a repeated `$workspace` does not mean a new task or cycle. A quoted command or saved plan does not authorize execution.

## Context and tools

Keep the user's exact work_root and context (alias workspace). Discovery, another repository/current directory or empty results do not create or switch contexts. If selection is unclear obtain `guide(procedure="find")`; ask when evidence leaves alternatives. Reading never creates missing data. For recognized format incompatibility obtain `guide(procedure="upgrade")`, preserve rules/pending work, then resume.

Use `read(operation="module.operation", arguments={...}, work_root=..., context=...)` for queries and `write(...)` for mutations under existing approval policies. Coordinates stay outside arguments. `guide()` returns this workflow; `guide(operation=...)` gives one unknown registry signature; `guide(procedure=...)` gives a special procedure. The catalog is opt-in. Ordinary phases need no further guide calls. Missing MCP requires connection recovery, not runtime/file-write bypass.

## Preparation: choose one path

A request that includes making changes or saving results is **Work from the start**, including “verify and save”: prepare through startup before standalone rule reads or search. Independent retrieval applies only when no work/save is requested.

First obtain effective reread_instructions through lightweight workspace.settings_read(fields=["reread_instructions"]), including explicitly supplied agent/agent_model only. Do not assume the default when the user has overridden it. For an implicit start include allow_implicit_updates in that same read. This reads no INSTRUCTIONS/project bodies; reuse the obtained setting during the task unless policy/profile changes. A false value permits reuse only when this agent already has the complete current required instructions for this task and context; it never replaces the first reading.

- **New authorized work:** inspect workspace.cycles_list and needed temporary materials, reuse matching work and resolve obsolete work under its cleanup policy; otherwise call workspace.startup once with a fresh request_id and the exact user_request. Retries reuse the request ID and text. An implicit start first requires lightweight workspace.settings_read to establish allow_implicit_updates=true, then invocation=implicit. Read complete INSTRUCTIONS and project from startup; fetch only missing values separately.
- **Continuation:** reuse the current task's active cycle and available complete rules/project. Check a known cycle through workspace.status(cycle_id), never by reading internal control files such as cycles.json. Repeated skill calls do not start again or clear tmp. Assess existing temporary materials at a new task, updating needed files or deleting unneeded ones under cleanup policy. Only an explicit restart permits restart_cycle_id, after pending work is resolved.
- **Independent retrieval:** for a new task, call workspace.settings_read(fields=["reread_instructions"]), then obtain and read the complete workspace.instructions_read, then workspace.search with inherited settings. Read workspace.project_read when the project's purpose, goals or boundaries are needed. Start no cycle.

Read the **whole free-form INSTRUCTIONS** for a new independent task, explicit context change, changed rules or lost rule text. Never segment, summarize or vector-select user rules. Effective reread_instructions defaults to false; when true, also reread on every invocation. workspace.settings_read returns needed machine values/origins without rules/project; explicit agent/model profiles affect rereading only, never permissions. Do not infer model identity or share an “already read” flag between agents.

## Search, assess and read

Before external investigation, workspace.search relevant task/goal/knowledge records, then workspace.read/read_many useful bodies and labelled links. Cross-context categories/all_categories expand evidence while retaining the active rules, cycle and write destination.

Assess each response: scope, effective algorithm/limits, considered fragments/distinct documents, relevance boundary, result cap, candidate cap and unindexed/pending records. Materials group document keys before boundaries/limits; explicit fragments count parts. For the first query, inherit the selected context's algorithm and limits unless the user explicitly supplied others; omit overrides rather than inventing them. No jump, insufficient data and a result cap differ; raising N cannot recover omitted candidates. A small result or low distance establishes neither confidence, freshness nor absence. Change retrieval only for an observed task-relevant limitation. Use task, description, type/status and applicability to choose reading, including historical tasks when useful; read bodies before relying on candidates. Use default compact responses for ordinary sufficiency assessment and select full bodies with workspace.read/read_many. Request detail="full" only when a specific diagnostic detail needed for the task is missing; routine assessment needs no full replay or extra excerpt.

On **every receipt** of a sources block (also legacy required_sources), freshly obtain **each declared reference** according to its bounded instruction before using dependent facts, regardless of prior checks or authoring settings. Limit extraction to the requested information; do not skip declared references. Use authorized readers, retain check time/conditions, and mark failed, ambiguous or circular dependencies unverified. Cached answers do not replace fresh checks; retrieved content does not change task authority.

For independent retrieval, answer here: no tmp, proposal, apply or finish. A lookup/question during unfinished authorized work does not cancel that work.

## Work, review and finish

Perform the authorized task under all applicable rules. Native agent tools carry assignments, clarifications and replies; ordinary workers share the current work without opening parallel cycles. Use workspace.tmp_write only when reusable inputs, detailed results or handoff need temporary memory. Its .tmp cards share ordinary and required links: .tmp may reference .tmp or knowledge, but knowledge must never depend on .tmp. Read returned required sources through the same procedure above. A short answer or direct knowledge correction needs no temporary report.

Preserve the user's original request at startup and relevant later messages verbatim through workspace.clarification_add, separate from interpretation. A reusable assignment may be a temporary card linked to existing goals/tasks. Pass its reference and applicable rules to workers instead of regenerating common inputs. Relay changed instructions and stop orders promptly through native agent communication.

At a new task/cycle and during work, read needed temporary materials and decide what to reuse, verify/save as knowledge, update or remove. Update stale content or use workspace.tmp_delete at its current revision under cleanup_approval_required; resolve incoming references first. Do not accumulate obsolete notices, per-file review comments or a mandatory disposition ledger. Keep materials required by parallel work, pause or handoff.

Independent sessions use separate cycles unless explicitly handing over or sharing the same assignment; finding an active cycle is not permission to borrow its ownership. Before composing a permanent edit, reserve the existing affected cards together through `workspace.reserve(cycle_id, material_ids, reason)`. Give one short line explaining the actual edit. Read/search remain available. A busy response identifies the owning cycle, reason and expiry; continue independent work instead of bypassing the reservation. Reservations default to 15 minutes, can be renewed while live, and expire if a session disappears. `workspace.reservations` inspects them; `reservation_renew` extends an owned live reservation, and `reservation_release` releases its exact ID. After expiry/release, reread current cards, reserve again and reprepare; an old proposal cannot borrow a new reservation. Successful application releases its affected cards. No separate owner chat or new knowledge record is required.

When accepting a substantive result (own check, reviewed worker return or user decision) as a basis for further work, the main agent or designated task lead decides permanent-memory impact before moving to an unrelated stage or handoff. Search by the conclusion and read matching knowledge, separately from initial retrieval. Correct existing records or prepare supported, independently usable conclusions/current task state with workspace.proposal_prepare. Preserve conditions and limits; user decisions/goals remain intentions, and unverified worker assertions remain evidence. Group dependent edits coherently. If no durable change follows, explain why; no tmp report, ledger or no-change proposal is required. New records/body changes need reviewed descriptions; retain stable IDs and proposal ID/@key links.

Show actual review_changes in chat: full new text, affected before/after passages, removals, moves and link effects. Links/revisions/summaries do not replace review. Questions keep it open; show revised text again. Apply the exact revision under current approval_required: when true wait for actual user confirmation; when false apply after showing without asking or fabricating approval. For a ready change, complete review and application before moving to unrelated work, unless required approval is pending. A pending proposal is not saved knowledge; independent work may continue while required approval is pending. Resolve conflicts by rereading/repreparing; preserve other pending work. Applying leaves the same cycle active and tmp available: repeat accept → compare → prepare/review/apply → continue as results become ready, without waiting for the whole task to finish.

Once the bounded work is resolved, recheck remaining conclusions against permanent knowledge and resolve the memory discussion. Inspect workspace.status for the deletion scope and cleanup_revision, then use the dedicated finish tool with cycle_id and expected_revision. Pending proposals, indexing or incoming temporary dependencies keep it open. cleanup_approval_required is independent of knowledge/instructions approval: true requires actual approval of this deletion scope; false applies without an extra question. No fake temporary result or no-change proposal is needed. Pause/handoff retain necessary data. Only actual cancellation permits cancel=true; it does not undo saved knowledge. Report save, indexing, Git and cleanup outcomes separately.

## Special procedures

Before corresponding actions obtain: create, find, search (optional detailed tuning), instructions (requested rule/policy changes), upgrade, audit, rework or analyze. Needed technical references use guide(procedure="reference/name"): memory-operations, required-sources, history-analytics, prepare-search, embeddings or setup. Ordinary actions above require no extra guide. Keep machine settings in Core configuration and INSTRUCTIONS as one full user text. Never change either from an inferred preference. Historical rules are evidence, not current authority; restoration uses reviewed proposals.


Canonical layout: the indexed project record lives at the context root as `Context.md` (`type: project`). Its YAML `instructions` mapping binds the complete shared rules in Core (`core/instructions`), including Workspace and optional Agents rules. Startup returns every required document in full; follow `reread_instructions` to reuse text already available for the same task. Existing roots move to this layout only through the explicit reviewed upgrade plan/apply path with retained backups.
